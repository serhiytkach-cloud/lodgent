# 0007. Attribute profile: provenance, verified extraction, publishing

Date: 2026-10-11 · Status: accepted

## Context
Agents filter and rank hotels on attributes ("sauna", "dogs allowed", "room with bathtub"). A wrong "yes" leads to a booking the guest regrets, so the profile has to be trustworthy. The facts come from three places: the PMS set-up, the hotel's website, and the hotel's own edits. The spec requires evidence for every extracted fact, a review step, and an explicit publish step before agents see anything.

## Decision
- **Controlled vocabulary.** `packages/taxonomy` holds 153 attributes in 11 categories. Each has a stable code, a value type (boolean, enum, number with unit, text), whether it applies to the property, rooms or both, an importance (1–5) that drives completeness and gaps, synonyms (keyword matching and, in M4, mapping agents' free text to codes) and a schema.org mapping. Codes are never renamed, only deprecated.
- **One row per source.** `attribute_assignments` is unique per (property, scope, attribute, source). Sources are `pms`, `website` (keyword matcher), `ai_extracted` (Claude) and `hotel`. Machine sources write `suggested` rows with confidence and evidence (`{url, snippet}`); a re-import updates the source's own row and resets a changed value to `suggested`, while an unchanged value keeps its status. The **effective value** is the most recently approved row; the hotel's own value wins ties. Agents, the public profile and JSON-LD only see effective values.
- **Verified extraction.** Claude (`ANTHROPIC_MODEL`, default `claude-sonnet-5-5`) gets the vocabulary as a cached system block and up to 90k characters of page text, and answers through structured outputs (`output_config.format` with a Zod schema) with a verbatim quote and URL per attribute. We then drop any item whose code is unknown, whose value doesn't normalize to the attribute's type, whose URL isn't one of the crawled pages, whose confidence is below 0.5, or **whose quote does not appear in that page's text** (normalized match; an ellipsis splits a quote into fragments that must appear in order). Room-level facts must name an existing room type. Refusals and API errors fail the import with a clear message and write no suggestions. Server-side fallbacks are enabled. Without an API key, an offline keyword matcher (same verification) keeps local development and tests free.
- **PMS mapping** runs after every sync: included breakfast or half board in rate plans, room sizes and keywords in unit-group descriptions, family capacity. These are `pms` suggestions; the hotel still approves them.
- **Crawling** is polite and SSRF-safe: robots.txt honoured (Crawl-delay raised, capped at 5 s), same host only, at most 30 HTML pages, likely-relevant paths first, 2 MB / 15 s per response, redirects re-validated hop by hop, and a connection-level DNS check that refuses private, loopback, link-local and metadata addresses (no DNS-rebinding window). `CRAWL_ALLOW_PRIVATE_NETWORKS` exists for the local fake sites and is rejected in production.
- **Publishing** requires a PMS connection, at least one sellable rate plan exposed to agents, an 80+ character description and 5+ approved attributes. Publishing writes the property's embeddings (`property_embeddings`, pgvector 512 dims, HNSW cosine), and any later profile change re-embeds via the outbox. A content hash per document avoids paying for unchanged text. Embeddings come from Voyage (`voyage-3.5`) or OpenAI (`text-embedding-3-small`) at 512 dimensions; a deterministic local hash embedding is used in dev and tests.
- **JSON-LD** for the hotel's own site is generated from effective values only: `Hotel` with `amenityFeature` (`LocationFeatureSpecification`), `petsAllowed`, check-in/out times, `containsPlace` `HotelRoom`s with `occupancy`, `floorSize` and room amenities, and `makesOffer` `Offer`s pointing at the public profile. The public profile page (`/hotels/[slug]`) embeds the same JSON-LD.

## Consequences
- Every fact an agent sees was approved by a person at the hotel or set by them. Provenance is visible in the editor, and the quote that justified each suggestion is one click away.
- Paraphrased quotes from the model are dropped rather than "fixed". This costs some recall; the import stats show how many were dropped so we can tune the prompt.
- Re-imports never overwrite a hotel's decision silently: an unchanged suggestion keeps its approved or rejected state, and a changed one goes back to review.
- Embeddings are tied to the model name; switching providers re-embeds everything on the next refresh.
